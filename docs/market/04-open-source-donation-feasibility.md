## 1. Executive Summary — 결론 5줄

1. **[판정] "공개 + 기부"를 *수익 사업*으로 보면 NO-GO다.** 문헌 기저율과 제품 특성을 대입한 확률가중 기대수익은 **연 $100~300(중심 $197)** 이다. 이 금액은 4개 대안 모두에서 **노이즈 수준으로 구분되지 않는다** — 즉 **수익으로 안을 고르는 것 자체가 통계적으로 무의미하다.**
2. **[판정] "공개 + 기부"를 *비용 회수 + 평판 자산*으로 보면 GO다.** 구현 비용이 **사실상 0**이기 때문이다. README 후원 섹션·실링크가 이미 존재하고(**[실측]** `README.md` `## 후원`·`## Support`, Ko-fi·Sponsors 배지), 라이선스 검증·서명이 필요 없다.
3. **[기저율] GitHub Sponsors의 중위 수입은 사실상 $0이다.** 누적 지급 **$50M+ / 수혜 개발자 49,000명 ≈ 1인당 누적 $1,020**, 이를 7.4년으로 나누면 **월 $11.5** [검색+추정]. 상위 유지관리자 $100k+/년이 총액을 흡수하므로 **나머지 약 48,900명의 중위 누적 수입은 $0~수십 달러**로 추정된다.
4. **[적합도] WallMagic의 기부 적합도는 100점 만점에 34점이다.** 최대 감점 요인은 **사용 빈도**다 — 배경화면 앱은 한 번 설정하면 잊히고, 트레이 상주·자동시작이 **0줄**이라 반복 접점이 없다. **기부는 "매일 쓰는 것"에서 나온다.**
5. **[기회비용] MIT로 공개하면 유료화 경로가 *영구 소멸*한다.** MIT는 상업적 이용을 허용하므로, 누구나 포크해 유료 판매할 수 있다. 이는 **되돌릴 수 없는 단방향 결정**이며, 4안 중 유일하게 비가역적인 선택이다.

### 종합 판정 (상세는 §7)

| 질문 | 판정 |
|---|---|
| 공개 + 기부를 **수익 모델**로 | ❌ **NO-GO** (기대 연 $197, 상방 $10k/년은 0.5% 확률) |
| 공개 + 기부를 **비용 회수·평판 자산**으로 | ✅ **GO** (구현 비용 0, 비가역성 수용 전제) |
| 4안 중 최종 권장 | ✅ **A안 — 기부 단독(공개)** |
| 착수 전 선행 조건 | ⚠️ **트레이 상주 + 자동시작**(기부 적합도 34→54점의 유일한 큰 레버) |

## 2. 기부 모델의 기저율 — "얼마나 되는가"의 실측 근거

기부 모델 판정에서 가장 중요한 것은 낙관이 아니라 **기저율**이다. 먼저 총량, 다음 분포, 다음 전환율 순으로 확인한다.

### 2.1 총량 — GitHub Sponsors에 실제로 얼마가 흐르는가

| 지표 | 수치 | 등급 |
|---|---|---|
| 누적 지급액 | **$50M+** | [검색] |
| 수혜 개발자 수 | **약 49,000명** | [검색] |
| 1인당 **누적** 평균 | **$1,020** ← $50M ÷ 49,000 | [추정: 산술] |
| Sponsors 운영 기간 | 약 **7.4년** (2019-05 출시 ~ 2026-10) | [추정] |
| 1인당 **월** 평균 | **$11.5** ← $1,020 ÷ 88.8개월 | [추정: 산술] |
| 평균 개인 후원액 | **$8/월** | [검색] |
| 평균 기관 후원액 | **$200/월** | [검색] |
| 중간 tier 유지관리자 | $500~$5,000/월 | [검색] |
| 최상위 유지관리자 | $100,000+/년 | [검색] |

**핵심 해석**: 누적 $1,020은 **"후원을 한 번이라도 받은 49,000명"의 평균**이다. 기부를 요청했지만 **한 푼도 못 받은 프로젝트는 이 분모에 없다.**

### 2.2 분포 편중 — 평균이 아무것도 말해주지 않는 이유

$50M 총액과 "최상위 $100k+/년"을 함께 놓으면 산술이 강제된다.

```
상위 100명 × $100,000/년 × 5년 = $50,000,000  ← 총액 전부
```

즉 **총액 대부분이 상위 수백 명에 집중**되며, 나머지 약 48,900명의 몫은 잔여로 계산된다 [추정: 산술]. 이 구조에서 **중위(median) 수입은 $0에 수렴**한다.

| 분위(추정) | 조건 | 누적 수입 [추정] |
|---|---|---|
| 상위 0.2% (≈100명) | 유명 OSS 저자 | $100k+/년 |
| 상위 2% (≈1,000명) | 중간 tier 유지관리자 | $500~$5,000/월 |
| **중위 (≈24,500명)** | **후원 1회 이상 받은 개발자** | **$0 ~ 수십 달러** |
| 기부 요청만 하고 못 받은 프로젝트 | Overney 표본 25,885건 중 다수 | **$0** |

> **읽는 법**: "GitHub Sponsors로 $100k/년 받은 사람이 있다"는 사실은 **당신의 기대값에 관한 정보가 아니다.** 그건 상위 0.2%의 이야기이고, 판정에 써야 하는 것은 중위다.

### 2.3 [문헌] Overney et al., ICSE 2020 — "How to not get rich"

이 분야에서 가장 직접적인 실증 연구다. 결론이 제목에 있다.

| 발견 | 원문 취지 | 등급 |
|---|---|---|
| 규모 | **25,885개** GitHub 프로젝트가 기부를 요청 | [문헌] |
| 전업 자금 | 기부를 받지만 **"전업 엔지니어링 직책을 지원할 만큼은 거의 없다"** | [문헌] |
| 활동량 상관 | **"기부 수령이 프로젝트 활동량을 높인다는 강한 증거를 찾지 못했다"** | [문헌] |
| 지출 패턴 | **40%(24/60)는 모금액의 25% 미만만 지출**, 15%(9/60)만 75% 초과 지출 | [문헌] |
| 지출 용도 | 여행·웹호스팅·**개인 경비** 등 비엔지니어링 영역 다수 | [문헌] |
| 함의 | 기부는 **"존속 가능한 자금원"이 아니라 "보조 수단"** | [문헌] |

**WallMagic에 대한 직접 함의 3가지**

1. **25,885개 프로젝트가 이미 기부를 요청하고 있다.** 기부 요청은 차별화 요소가 아니다 — **경쟁이 아니라 소음**이다.
2. **"전업 자금이 안 된다"는 것은 이 표본의 다수 결과다.** WallMagic이 예외가 될 근거를 제시해야 한다.
3. **지출 투명성이 신뢰의 핵심 변수다.** 40%가 모금액을 거의 쓰지 않는다는 사실은, **"이 돈이 어디 갔는지 보여주는 프로젝트"가 신뢰를 얻는다**는 역신호다. → §7 실행 권고에 반영.

### 2.4 전환율 — 다운로드 → 기부는 얼마인가

| 단계 | 전환율 | 등급 |
|---|---|---|
| OSS 사용자 → **유료 플랜** | 약 **2%** (10,000명 중 200명 예시) | [검색] |
| OSS 사용자 → 유료 (일반 산업 범위) | 0.5~2% | [검색·추정] |
| **다운로드 → 기부** | **0.1~1% (중심값 0.3%)** | **[추정]** |

**왜 기부가 유료보다 훨씬 낮은가** — 구조적 이유 3개:

1. **대가관계가 없다.** 유료는 "기능을 받으니 돈을 낸다"는 등가 교환이고, 기부는 **순수 호의**다. 호의는 예산 항목이 아니다.
2. **강제성이 없다.** 유료는 게이트(라이선스 검증)가 전환을 밀어붙이지만, 기부는 **밀어붙이는 힘이 0**이다.
3. **Overney 표본이 이를 뒷받침한다.** 25,885개 프로젝트가 요청해도 전업 자금이 안 되는 것이 다수 결과다.

> **중심값 0.3%의 근거**: 유료 전환 2%의 **약 1/7**. 기부가 유료의 10~20% 수준이라는 것은 보수적 가정이며, **이 값을 실측한 데이터는 없다** [추정]. §8 참조.

## 3. WallMagic 특성별 기부 적합도 스코어카드

기부 심리는 기능 목록이 아니라 **심리적 조건**에서 발생한다. 7개 축으로 채점했다(10점 만점, 가중 합산).

### 3.1 채점 기준과 결과

| # | 축 | 가중 | 점수 | 근거 [실측] |
|---|---|---|---|---|
| 1 | **사용 빈도·일상 침투** — 매일 쓰는가 | **25%** | **2/10** | 배경화면은 **한 번 설정하면 잊히는** 앱. `grep "tray\|autostart"` → 앱 코드 **0줄**(`gen/schemas` 자동 생성물만). **반복 접점이 없어 감사가 축적될 자리가 없다** |
| 2 | **대체 불가성** — 다른 걸로 안 되는가 | 15% | **5/10** | `IDesktopWallpaper` 모니터별 **개별 프롬프트**는 희소. 그러나 무료 대안 10종 존재, **JBS는 Windows 영구 무료 선언** |
| 3 | **가시적 성과** — 내 돈이 뭘 만들었나 | 10% | **4/10** | 릴리스 2건(nsis/msi)·CHANGELOG 존재. 그러나 **공개 전이라 외부에서 볼 수 없음**(`api.github.com/.../WallMagic` → **HTTP 404**) |
| 4 | **공동체·정체성** — 속하고 싶은가 | 15% | **1/10** | 스타 0 · 기여자 0 · 저장소 **비공개** · Discord/이슈 없음 |
| 5 | **유료 대안 존재** — 돈 내는 게 당연한 영역인가 | 15% | **2/10** | 카테고리가 **무료 포화**(Spotlight·Bing·Lively·JBS·Pollinations). "왜 돈 내지"가 먼저 나오고, 기부는 그 다음 문제 |
| 6 | **정직한 한계 공개** — 신뢰할 수 있는가 | 10% | **8/10** | `README.md` 보안 절에 CSP·서명·업데이터·평문 키 저장을 **자진 공개**. `SECURITY.md`에 "알려진 한계" 명시. **이 항목은 실제로 강하다** |
| 7 | **저자 가시성** — 누가 만드는지 보이는가 | 10% | **5/10** | `uptodatelabs` 단일 조직. 개인 이력·블로그·X 계정 연결 **없음**(실측) |

**가중 합계**:
```
2×0.25 + 5×0.15 + 4×0.10 + 1×0.15 + 2×0.15 + 8×0.10 + 5×0.10
= 0.50 + 0.75 + 0.40 + 0.15 + 0.30 + 0.80 + 0.50
= 3.40 / 10  →  **34 / 100**
```

### 3.2 판정 — 왜 34점인가

**감점의 8할이 "사용 빈도" 한 축에서 나온다.** 기부는 기능의 우수성이 아니라 **반복 노출**의 함수다. 매일 보는 앱은 "이거 공짜인데 괜찮나"라는 죄책감을 만들고, 그게 기부로 전환된다. 배경화면 앱은 그 감정이 만들어지기 전에 **잊힌다.**

**결정적 역설**: WallMagic은 **일부러 잊히도록 설계된 앱**이다. "설정하고 잊어버리기"가 좋은 배경화면 앱의 미덕인데, **그 미덕이 기부 모델의 적**이다. 유료 모델은 잊혀도 되지만(이미 결제됨), 기부 모델은 **잊히면 수입이 0**이다.

### 3.3 개선 시뮬레이션 — 어디까지 올라가는가

| 조치 | 축 | 점수 변화 | 총점 |
|---|---|---|---|
| (현재) | — | — | **34** |
| **트레이 상주 + 자동 시작 + 시나리오 자동 변경** | #1 사용 빈도 2→**7** | +1.25 | 46 |
| **공개 + 스타·이슈·Discord 개설** | #4 공동체 1→**5** | +0.60 | **52** |
| 릴리스 노트·X 계정으로 저자 가시화 | #7 저자 5→**7** | +0.20 | 54 |
| **모든 개선 후 상한** | — | — | **54 / 100** |

> **핵심**: 모든 개선을 다 해도 **54점**이다. 이 축들이 **구조적으로 낮기 때문**이다 — 정적 배경화면 카테고리 + 무료 포화 + 개인 프로젝트. **기부 모델의 상한이 여기서 결정된다.**

## 4. 시나리오별 월 수익 × 확률 매트릭스

### 4.1 시나리오 정의

도달(reach)을 GitHub 스타·월 다운로드로 정의하고, 기부 전환 §2.4의 **0.3%** 를 적용했다. 월간 후원자는 누적의 20%가 recurring($5/월)으로 전환된다고 가정 [추정].

| 시나리오 | 스타 | 월 다운로드 | 월 신규 기부자 | 누적 월간 후원자 | **월 수익** | **확률** |
|---|---|---|---|---|---|---|
| **S0** 무명 유지 | <50 | <100 | 0.3 | 0 | **$1** | **70%** |
| **S1** 발견됨 | 100~500 | 1,000 | 3 | 2 | **$22** | **20%** |

확률 합계 100.02% (반올림).

### 4.2 확률가중 기대값

```
S2는 2개월 피크 후 S1 수준으로 감쇠 → 연평균 월수익 = (145×2 + 22×10) ÷ 12 = $42.5

EV(월) = 0.70×1 + 0.20×22 + 0.07×42.5 + 0.025×160 + 0.005×860 + 0.0002×4,800
       = 0.70 + 4.40 + 2.975 + 4.00 + 4.30 + 0.96
       = $17.3 / 월
```

**기대 연 수익 ≈ $208 / 년** (80% 신뢰구간 $0~$60/월)

### 4.3 해석 — 세 문장

1. **70% 확률로 월 $1 이하다.** 즉 **"공개했지만 아무 일도 일어나지 않는"** 것이 가장 가능성 높은 결과다.
2. **상방은 존재하지만 확률이 0.02~0.5%다.** S4($860/월 = 연 $10.3k)는 **200번 중 1번**이다. 이걸 계획에 넣으면 안 된다.
3. **바이럴(S2)이 가장 위험한 시나리오다.** 7% 확률로 2개월간 $145/월을 보고 "된다"고 판단하면, 3개월 후 $22/월로 돌아온 뒤 전략을 잘못 바꾼다. **S2는 추세가 아니라 스파이크다.**

### 5.3 결정적 관찰 — 기대 수익으로는 안을 고를 수 없다

```
A: $208/년   B: $130/년   C: $110/년   D: $155/년
```

**네 안의 차이는 $110~208 범위, 즉 약 $100 폭이다.** 이는 시나리오 확률의 오차 범위보다 작다. **즉 "어느 안이 더 돈이 되는가"는 이 데이터로 판별 불가능하다.**

따라서 안을 가르는 기준은 수익이 아니라 **세 가지**여야 한다:

| 실제 판별 기준 | 승자 |
|---|---|
| **① 구현 비용** (지금 얼마를 더 투입해야 하는가) | **A** (≈ $0) |
| **② 되돌릴 수 있는가** (선택권 보존) | **C·D** (A는 불가) |
| **③ 상방의 꼬리** (성공 시 얼마까지) | **D** (연 $5k, 1.5%) |

**A와 D가 정면 충돌한다.** A는 "비용 0 · 비가역", D는 "비용 높음 · 가역 · 꼬리 큼". 나머지 B·C는 **두 축 모두에서 열등**하다 — 비용은 A보다 높고(라이선스 검증 0줄 구현 필요), 가역성은 D보다 낮거나 같으며, 평판 자산은 A보다 낮다. **B·C는 지배당한다(dominated).**

### 5.4 A vs D — 최종 대결

| | **A. 기부 단독** | **D. 클로즈드 유료** |
|---|---|---|
기대 연 수익 | $208 | $155 |
필요 선행 작업 | **없음** | 라이선스 검증(0줄→구현) · 서명 · 트레이 |
선행 작업 예상 기간 | **0일** | **1~2주** (P0 5건 중 3건) |
실패 시 잃는 것 | **유료화 선택권** | **시간과 비용** (판매 0건이면 순손실) |
실패 시 남는 것 | **공개 이력·평판** | **없음**(비공개) |
되돌리기 | ❌ 불가 | ✅ 가능 |

**결론**: 기대 수익이 노이즈 수준이라면, **비용이 0이고 실패해도 자산이 남는 쪽(A)** 이 합리적이다. 단 **A를 고르는 순간 D의 상방(연 $5k, 1.5%)을 영구히 포기**한다는 사실을 명시적으로 수용해야 한다.

## 6. 기회비용 정량화 — "공개하면 무엇을 잃는가"

이 절은 지시 고찰 (4)에 대한 직접 답이다. **공개는 공짜가 아니다.**

### 6.1 MIT 공개의 법적 효과

| 항목 | MIT 조항 | 결과 |
|---|---|---|
| 상업적 이용 | 허용 | **누구나 포크해 유료 판매 가능** |
| 재배포 | 허용 | 무료 재배포 가능 |
| 2차적 저작물 | 허용 | 경쟁 제품 파생 가능 |
| 요구 사항 | 저작권 고지 유지 | 상표·브랜드는 보호되지 않음 |
| **유료화 가능성** | — | **소스가 MIT면 누구나 무료 빌드 → $14.99 판매 성립 불가** |

```
D안(유료 $14.99) × A안(MIT 공개) = 성립하지 않는 조합
```

**이것이 기회비용의 핵심이다.** 소스가 MIT로 공개된 순간, 유료 라이선스 판매의 근거(배포 독점)가 사라진다. **A안과 D안은 배타적이며, A를 고르면 D의 상방(연 $5k, 1.5% 확률)이 영구 소멸한다.**

### 6.2 그럼에도 A가 합리적인 이유 — 비대칭

| 상황 | A안 결과 | D안 결과 |
|---|---|---|
| 실패(80%) | **공개 이력 + 스타 + 학습 자산** 남음 | **비용 손실 + 흔적 없음** |
| 중간 성공(18%) | 연 $200~2,000 | 연 $100~500 |
| 대성공(1.5%) | 연 $10k (0.5%) | **연 $5k (1.5%)** |

**비대칭의 요점**: 실패 확률이 80%인데, **실패했을 때 A는 자산이 남고 D는 남지 않는다.** 이는 전형적인 **비대칭 베팅(asymmetric bet)** 구조이며, 기대값이 비슷할 때는 **손실이 작은 쪽**을 골라야 한다.

### 6.3 제3의 선택지 — A′ (비상업 소스 공개)

지시된 4안 외에, **비가역성을 완화하는 변형**이 존재한다. 이는 "공개+기부"의 기회비용을 줄이는 유일한 방법이므로 명시한다.

| | **A. MIT 공개** | **A′. 비상업 소스 공개** (예: PolyForm Noncommercial / BSL) |
|---|---|---|
소스 열람 | ✅ | ✅ |
기부 유도 | ✅ | ✅ |
기여 수용 | ✅ | ✅ |
**상업적 이용** | ✅ 허용 → **유료화 소멸** | ❌ 금지 → **유료화 보존** |
OSI 오픈소스 인정 | ✅ | ❌ ("오픈소스"라 부를 수 없음) |
커뮤니티 반응 | 호의적 | **일부 반발** (스타·기여 감소) [추정] |
기부 전환 | 기준 | **기준보다 낮음** (신뢰 감소) [추정] |

**A′의 트레이드오프**: 유료화 선택권을 보존하는 대신, "오픈소스"라는 정체성과 그에 따른 커뮤니티 호의를 일부 포기한다. **기부 적합도가 이미 34점인 상황에서 이 손실은 작지 않다.** 그러나 되돌릴 수 없는 결정을 피한다는 점에서 **위험 회피 성향이 강하면 A′** 가 합리적이다.

> **이 변형은 지시된 4안에 포함되지 않으므로 최종 권장에서는 A안을 채택하고, A′는 대안으로 병기한다.**

### 7.2 최종 권장 — **A안 (기부 단독, MIT 공개)**

**권장 이유 3개**

**단, 다음을 명시적으로 수용해야 한다 (수용하지 못하면 A를 선택하면 안 된다)**

- ⚠️ **유료화 선택권을 영구 포기한다.** MIT 공개 후 $14.99 판매는 성립하지 않는다. 되돌릴 수 없다.

## 9. 결론 — 한 문단

"공개 + 기부"는 **수익 모델로는 성립하지 않는다.** 문헌 기저율(GitHub Sponsors 중위 수입 ≈ $0, Overney 25,885개 프로젝트의 다수가 전업 자금 확보 실패)과 WallMagic의 기부 적합도(**34/100**, 최대 감점은 "설정하고 잊는 앱"이라는 구조적 특성)를 대입하면, 확률가중 기대수익은 **연 $208, 80% 구간 $0~720** 이다. 이는 4개 대안 모두에서 **노이즈 수준으로 구분되지 않는다.**

그러나 **A안(기부 단독)은 구현 비용이 ≈ 0이고, 실패해도 공개 이력이 남는 비대칭 베팅**이다. 반면 D안(클로즈드 유료)은 라이선스 검증 **0줄**·코드 서명 **부재**·트레이 **0줄**의 3건을 먼저 구현해야 하고, 그 비용은 기대 수익(연 $155)을 수년간 회수하지 못한다. **B안(오픈코어)과 C안(무료+Pro)은 A·D에 지배당한다.**

**따라서 최종 권장은 A안(기부 단독, MIT 공개)이며, 그 대가로 유료화 선택권을 영구 포기함을 명시적으로 수용해야 한다.** 수용할 수 없다면 A′(비상업 소스 공개)로 비가역성을 완화하거나, D안을 선택하고 **선행 3건을 먼저 구현**해야 한다. 어느 쪽이든 **트레이 상주 + 자동 시작**은 공통 선행 조건이다 — 그것이 없으면 기부든 유료든 **접점 자체가 없다.**
