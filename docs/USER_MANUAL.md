# WallMagic 사용 매뉴얼 (v1.0 — Windows 전용 GUI)

> **대상 버전**: `wallmagic-core` / `wallmagic-app` v1.0.0 (제품 표기 v1.0 — 첫 공개 릴리스)
> **플랫폼**: Windows 10 (1809+) / Windows 11 (64-bit)
> **인터페이스**: **Windows GUI 프로그램 (Tauri v2 + React)** — CLI 인터페이스는 폐기되었습니다.
> **관련 문서**: [`ARCHITECTURE.md`](./ARCHITECTURE.md) (GUI 아키텍처), [`development-plan.md`](./development-plan.md) (개발 계획서), [`VERIFY_ALL_FEATURES.md`](./VERIFY_ALL_FEATURES.md) (전기능 검증 결과)

---

## 1. WallMagic란 무엇인가

WallMagic은 Windows PC의 바탕화면을 **검색 · 생성 · 적용 · 복원**하는 Windows 전용 데스크톱 프로그램입니다.

**창을 닫아도 트레이에 남아** 배경 전환을 계속 수행하며, 언제든지 "이전 배경으로 복원"으로 되돌릴 수 있습니다.

| 핵심 기능 | 설명 |
|---|---|
| **① 검색** | 내 PC 이미지 폴더(라이브러리 + Pictures, 또는 지정 폴더)와 **원격 이미지 검색**을 함께 사용합니다. 키워드·해상도로 걸러 썸네일로 보여줍니다. |
| **② 생성** | 테마 프롬프트로 1920×1080 배경을 만듭니다. 공급자 **5종** — `Pollinations`(무료·키 불필요) · `Cloudflare Workers AI` · `OpenAI Images` · `Puter`(WebView SDK) · `검색`. 우선순위대로 폴백하며 생성하고 라이브러리에 저장합니다. |
| **③ 적용** | 선택한 이미지를 검증·스테이징 후 바탕화면으로 적용합니다. **모니터별 개별 적용**과 6가지 배치 방식을 지원합니다. |
| **④ 복원** | 적용 전에 자동 저장한 스냅샷으로 이전 배경을 되돌립니다. |
| **⑤ 자동화** | **트레이 상주** · **로그인 시 자동 시작** · **시나리오 자동 업데이트**(주기 교체) · **자동 전환 규칙**(시간대·앱 시작·순환 + 디바운스/쿨다운) |

**안전성 (Zero-Black-Screen)**
- `IDesktopWallpaper` COM API를 1차로 사용하고, 실패 시 `SystemParametersInfoW`로 자동 폴백합니다.
- 적용 전 원본 배경을 스냅샷하므로, 실패하더라도 검은 화면으로 남지 않습니다.
- 640×480 미만이거나 손상된 이미지는 자동 제외됩니다.

> **현재 상태 (v1.0.0)**: 4개 핵심 액션 + 자동화 3종이 동작합니다. 상용 배포 전 남은 항목(코드 서명 · 자동 업데이트 · CSP · API 키 암호화)은 §8과 [`COMMERCIAL_READINESS.md`](./COMMERCIAL_READINESS.md) P0를 참조하세요.

## 2. 설치와 실행

### 2.1 시스템 요구 사항

| 항목 | 요구 사항 |
|---|---|
| OS | Windows 10 (1809 이상) / Windows 11 (64-bit) |
| 런타임 | WebView2 (Windows 10/11에 기본 탑재 — 별도 설치 불필요) |
| 디스크 | 약 50 MB |
| 메모리 | 유휴 시 약 40 MB |

### 2.2 설치

**방법 A — 인스톨러 (권장, 배포용)**
```
target/release/bundle/nsis/WallMagic_<version>_x64-setup.exe   ← NSIS 설치 프로그램
target/release/bundle/msi/WallMagic_<version>_x64_en-US.msi    ← MSI 설치 패키지
```

`<version>` 은 `Cargo.toml` 의 `[workspace.package] version` 을 따릅니다(현재 `1.0.0`).

> **검증 상태**: 인스톨러 2종은 실제 생성·업로드 확인된 이력이 있습니다(GitHub Release `v1.0.0`). 다만 **인스톨러 설치 실행 자체는 미검증**입니다 — 실제 설치를 시험하려면 방법 B/C의 개발 빌드(`run-app.cmd`)를 먼저 권장합니다.

실행 후 시작 메뉴의 **WallMagic** 바로가기로 시작합니다.

**방법 B — 소스에서 빌드 (개발용)**
```bash
# 1) 프론트엔드 의존성 설치 + 웹 번들 빌드
npm install
npm run build

# 2) Rust 코어 빌드 + 테스트
cargo build --workspace
cargo test --workspace

# 3) GUI 실행 (개발 빌드)
cargo run -p wallmagic-app
```

**방법 C — 릴리스 빌드 (배포 산출물 생성)**
```bash
npm install
npm run release:build      # tauri build — 웹 번들 → Rust release → NSIS/MSI
npm run release:check      # 산출물 실재 + 파일명 버전 일치까지 검증
```
산출물 (실측 경로):
- 실행 파일: `target/release/wallmagic-app.exe`
- NSIS 인스톨러: `target/release/bundle/nsis/WallMagic_<version>_x64-setup.exe`
- MSI 인스톨러: `target/release/bundle/msi/WallMagic_<version>_x64_en-US.msi`

`<version>` = `Cargo.toml` 의 `[workspace.package] version`(현재 `1.0.0`).

> 워크스페이스 루트의 `target/`이 번들 산출 루트입니다 (`src-tauri/target/`이 아님).

### 2.3 프로그램 시작

1. 시작 메뉴 또는 `target/release/wallmagic-app.exe` 실행 (인스톨러 설치 시 시작 메뉴의 **WallMagic** 바로가기)
2. 메인 창이 열리면 상단에 **현재 배경 · 적용 백엔드 배지 · 모니터 선택**이 표시됩니다
3. 좌측 패널에서 **검색** 또는 **생성**으로 시작합니다

## 3. 화면 구성

```
┌────────────────────────────────────────────────────────────┐
│ WallMagic Studio       [백엔드 배지]        [모니터 선택 ▾] │
├──────────────────┬─────────────────────────────────────────┤
│ ① 검색           │                                         │
│  [키워드]        │   ③ 미리보기 (선택된 이미지)              │
│  [검색 폴더]     │      ┌───────────────────────┐          │
│  [검색]          │      │                       │          │
│                  │      │   1920 x 1080 · 2.1MB  │          │
│  ┌────┬────┐     │      └───────────────────────┘          │
│  │썸  │썸  │     │   [배치 방식 ▾]                          │
│  │네일│네일│ ... │   [④ 바탕화면에 적용]                     │
│  └────┴────┘     │   [이전 배경으로 복원]                    │
│ ② 생성           │                                         │
│  [프롬프트]      │                                         │
│  [생성]          │                                         │
├──────────────────┴─────────────────────────────────────────┤
│ ⑤ 시나리오 (자동 업데이트) · 자동 전환 규칙                   │
├────────────────────────────────────────────────────────────┤
│ 현재 배경: <경로> · 이전 배경: <경로> · 상태 메시지          │
└────────────────────────────────────────────────────────────┘
```

### 3.1 상단 바
- **백엔드 배지**: 마지막으로 성공한 적용에 사용된 API (`IDesktopWallpaper (COM)` 또는 `SystemParametersInfoW (Fallback)`)
- **모니터 선택 드롭다운**: `모든 모니터` 또는 특정 모니터를 지정 (해상도·기본 모니터 표시)

### 3.2 좌측 패널 — ① 검색 / ② 생성
- **키워드**: 파일명 기준 대소문자 무시 부분 일치. 비우면 전체 목록.
- **검색 폴더**: 비우면 기본 루트(앱 라이브러리 + `Pictures`)를 탐색. 절대 경로 입력 시 해당 폴더만 탐색.
- **프롬프트**: 테마 문장 입력 (예: `aurora over icy mountains`).
- **배타 규칙**: 현재 공급자가 **검색**이면 생성 패널을, 생성 공급자이면 검색 패널을 표시하지 않습니다.

### 3.3 중앙 패널 — 결과 그리드
- 후보별 썸네일 + 파일명 + 해상도 + 용량 표시
- 카드를 클릭하면 오른쪽 미리보기에 선택됩니다
- **적용 가능한 이미지만** 표시됩니다 (640×480 이상 + 정상 디코딩)
- **최대 200건만 표시**됩니다 — 매칭된 전체 후보가 200건을 초과하면 상위 200건만 썸네일로 표시되고, 상태 바에 "N건 중 200건 표시"로 잘림이 안내됩니다 (IPC 페이로드·메모리 보호). 더 보려면 키워드를 좁혀 검색하세요.

### 3.4 우측 패널 — ③ 미리보기 / ④ 적용 · 복원
- **미리보기**: 선택 이미지의 큰 썸네일과 상세 정보(파일명·해상도·용량·전체 경로)
- **배치 방식**: `채우기(Fill)` / `맞춤(Fit)` / `늘이기(Stretch)` / `바둑판식(Tile)` / `가운데(Center)` / `스팬(Span)`
- **바탕화면에 적용**: 검증 → 스테이징 → 스냅샷 → 적용 순서로 실행
- **이전 배경으로 복원**: 스냅샷된 원본 배경으로 되돌림

### 3.5 하단 상태 바
- **현재 배경**: OS가 보고하는 실제 배경화면 경로
- **이전 배경**: 복원용 스냅샷 경로 (없으면 "스냅샷 없음")
- **상태 메시지**: 각 액션의 성공/실패 원문 (성공=녹색, 실패=빨간색)

### 3.6 ⑤ 시나리오 · 자동 전환 섹션
- **시나리오 (자동 업데이트)**: 주기 교체 설정 (URL·로컬 폴더·순서·seed·주기)
- **자동 전환 규칙**: 프로필 · 규칙(시간대/앱 시작/순환) · 디바운스/쿨다운 · 저장 버튼

## 4. 사용법

### 4.1 ① 검색

1. 좌측 **키워드** 입력 (예: `sunset`)
2. (선택) **검색 폴더**에 탐색할 폴더 절대 경로 입력
3. **검색** 버튼 클릭 또는 `Enter`
4. 중앙 그리드에 후보가 표시되고, 첫 번째 후보가 자동 선택됩니다

**동작 규칙**
- 파일명에 키워드가 포함된 이미지만 후보 (대소문자 무시)
- 지원 확장자: `.jpg`, `.jpeg`, `.png`, `.bmp`
- 최대 깊이 3단계까지 하위 폴더 탐색
- 640×480 미만 · 디코딩 불가 파일은 목록에서 제외
- **키워드가 비어 있으면 원격 검색은 생략**됩니다 (로컬 전체 목록만)
- 원격 결과는 `%LOCALAPPDATA%\WallMagic\online_cache\` 에 내려받은 뒤 로컬 결과와 병합됩니다
- 원격 응답이 실패해도 로컬 결과는 그대로 표시됩니다 (부분 실패 허용)
- 결과는 파일명 오름차순으로 정렬

### 4.2 ② 생성

1. 좌측 **프롬프트** 입력 (예: `cyberpunk rainy neon street in Seoul`)
2. **생성** 버튼 클릭
3. 생성된 이미지가 라이브러리에 저장되고 결과 그리드 상단에 자동 선택됩니다

**공급자 5종과 기본 우선순위**

| 순위 | 공급자 | 인증 | 비고 |
|---|---|---|---|
| 1 | `Pollinations` | **불필요** | 무료 · `&seed=N` 지원 |
| 2 | `Cloudflare Workers AI` | Account ID + API Token | 모델 선택 · flux 여부로 seed 적용이 갈림 |
| 3 | `OpenAI Images` | API Key | 유료 |
| — | `Puter` | WebView 로그인 | 브라우저 SDK 전용 — **Rust 백엔드에서는 스킵**되고 UI 경유로만 호출 |
| — | `검색` | 불필요 | 생성이 아니라 검색 공급자 |

- 공급자는 설정에서 **On/Off** 할 수 있고, **우선순위 순서대로 폴백**합니다. 하나가 실패하면 다음 공급자로 넘어갑니다.
- **seed 정책 3모드**: `random`(기본) / `incremental` / `fixed`. 같은 프롬프트라도 모드에 따라 같은 이미지가 나올 수도, 매번 다른 이미지가 나올 수도 있습니다.
- 저장 위치: 앱 라이브러리 (`%LOCALAPPDATA%\WallMagic\library\`). 파일명은 **중복되지 않도록 고유하게** 생성됩니다(`unique_output_path`).
- 생성 이력(프롬프트·공급자·seed·시각)은 사이드카와 `history.json`에 기록되어 **히스토리 창**에서 다시 볼 수 있습니다.
- 모든 공급자가 실패하면 상태 바에 실패 원인이 공급자별로 표시됩니다.

### 4.3 ③ 적용

1. 그리드에서 원하는 썸네일 클릭 → 오른쪽 미리보기에서 확인
2. **배치 방식** 선택 (기본: 채우기)
3. (다중 모니터) 상단 **모니터 선택**에서 대상 지정 — `모든 모니터`가 기본
4. **바탕화면에 적용** 클릭

**동작 규칙**
1. 이미지 검증 (존재 · 디코딩 · 640×480 이상)
2. `%LOCALAPPDATA%\WallMagic\active\` 로 **원자적 스테이징** (`staged_*.bmp` → `active_*.bmp` rename)
3. 현재 배경을 **스냅샷** (`state.json`의 `previous_wallpaper`)
4. `IDesktopWallpaper` COM으로 적용 → 실패 시 `SystemParametersInfoW` 폴백
5. 둘 다 실패하면 스냅샷된 원본을 재적용 (**검은 화면 방지**)

### 4.4 ④ 복원

1. **이전 배경으로 복원** 클릭
2. 스냅샷된 경로로 배경이 되돌아갑니다

**주의**: 한 번도 적용한 적이 없으면 `스냅샷 없음` 상태이며 복원할 대상이 없습니다.

### 4.5 ⑤-a 트레이 상주

**창의 X를 눌러도 종료되지 않습니다.** 창만 숨겨지고 앱은 트레이에 남아 자동 전환을 계속 수행합니다.

**트레이 아이콘 우클릭 → 메뉴 5종**

| 메뉴 | 동작 |
|---|---|
| **열기** | 숨겨진 메인 창을 다시 표시 |
| **숨기기** | 창 숨김 (배경 유지) |
| **시나리오 수동 선택** | 메인 창의 프로필 드롭다운을 엽니다 — **프로필이 1개 이상 있어야** 반응합니다 |
| **자동 시작 켜기/끄기** | §4.6을 창을 열지 않고 토글 |
| **종료** | **유일한 실제 종료 경로** |

> PC를 끄기 전에는 트레이 **종료**를 쓰거나 자동 시작을 켜 두는 편이 상태 파일 일관성에 안전합니다.

### 4.6 ⑤-b 로그인 시 자동 시작

켜는 경로는 셋 중 아무거나 같습니다 — UI 체크박스(`자동 전환 규칙` 섹션의 **로그인 시 자동 시작**), 트레이 메뉴, 또는 OS 시작 프로그램 설정(권장하지 않음).

**진실의 원천은 OS 등록 상태입니다.** 앱은 내부 플래그를 들고 있지 않고 매번 OS에 실제 등록 여부를 다시 묻습니다. 그래서 사용자가 시작 프로그램을 직접 해제해도 UI가 어긋나지 않고, 앱을 재시작하면 체크박스가 실제 상태로 돌아옵니다.

결과 메시지: 켜짐 / 꺼짐 / 실패 사유(권한·정책 차단 등).

### 4.7 ⑤-c 시나리오 자동 업데이트 + 자동 전환 규칙

두 계층이 맞물립니다.

```
[자동 전환 규칙]  매 60초 Rust 스레드가 평가  →  어떤 프로필을 쓸지 결정
      ↓  프로필 적용 = scenario.json 을 그 프로필 설정으로 덮어쓰기
[시나리오]        같은 60초 틱에서 실행      →  실제로 이미지를 생성·검색해 배경 교체
```

즉 **규칙은 "무엇을", 시나리오는 "실제 교체"** 입니다. "시간대별로 테마가 바뀌는" 동작을 원하면 둘 다 설정합니다.

#### 4.7.1 시나리오 (자동 업데이트)

| 항목 | 의미 |
|---|---|
| 자동 업데이트 | **ON** 이어야 실행됩니다 |
| 주기 (분, 최소 5) | 이미지 교체 주기. **5 미만은 거부**됩니다 |
| URLs | 원격 이미지 주소 목록 (한 줄에 하나) |
| 로컬 폴더 | 이 폴더의 이미지를 순환 |
| 순서 | 순차(sequential) / 랜덤(random) |
| seed | `fixed` / `incremental` / `random` |

#### 4.7.2 자동 전환 규칙

**1단계 — 프로필 만들기**
1. **새 프로필 이름** 입력 (예: `아침`, `업무`, `밤`)
2. **현재 설정으로 프로필 추가** 클릭 — 지금 시나리오 설정이 그대로 캡처됩니다
3. 목록에서 **적용**(즉시 수동 전환) / **삭제**

> **"적용"은 쿨다운을 소모하지 않습니다**(수동 전환이므로). 그래서 테스트할 때 마음껏 눌러도 자동 스케줄에 영향이 없습니다.

**2단계 — 규칙 추가**

| 트리거 | 설정 필드 | 발동 조건 |
|---|---|---|
| **시간대** | 시작 시(0–23) · 종료 시(1–24) · 요일(0=일…6=토, 콤마 구분) | 그 시간대 + 그 요일일 때 대상 프로필로 전환. **요일을 비우면 매일** |
| **앱 시작** | 대상 프로필 | 앱이 시작될 때 1회 |
| **순환** | 순환 주기(분) | 마지막 전환 후 N분 경과 시 **다음 프로필로 자동 순환** (대상 프로필 없음) |

**3단계 — 안전장치 2개** (여기서 대부분의 "왜 안 바뀌지?"가 발생합니다)

| 필드 | 의미 | 권장값 |
|---|---|---|
| **디바운스(초)** | 조건이 **연속으로** 이 시간만큼 참이어야 전환. 순간적 변화를 무시. `0`이면 즉시 | 30~60 |
| **쿨다운(초)** | 전환 **직후** 같은 규칙이 이 시간 동안 재발동 금지 | 600~1800 |

**4단계 — 저장과 즉시 확인**

| 버튼 | 하는 일 |
|---|---|
| **지금 규칙 평가** | 저장 없이 **현재 시각으로 1회 평가** — 결과를 바로 확인할 때 |
| **자동 전환 설정 저장** | `scenario_profiles.json` 에 기록. **이걸 눌러야 지속됩니다** |

**예시 ① 아침/업무/밤 3단**
```
프로필 3개: "아침"(밝은 테마) · "업무"(무채색) · "밤"(어두운 테마)
규칙 3개: 시간대 6→12 (요일 1,2,3,4,5) → 아침
          시간대 12→18 (요일 1,2,3,4,5) → 업무
          시간대 18→24 (요일 비움) → 밤
디바운스 30 / 쿨다운 900 → 저장
```

**예시 ② 4시간마다 순환**: 프로필 3~5개 생성 → 규칙 1개(트리거=순환, 주기=240) → 저장

#### 4.7.3 실행 주기와 알림

- **주기 실행 주체는 Rust 백그라운드 스레드**이며 **60초 고정**입니다. 창을 닫아 트레이에 숨겨도 계속 돕니다.
- 따라서 시나리오 주기를 5분으로 잡아도 **최대 60초 늦게** 실행되고, 시간대 경계(예: 12:00)도 **최대 60초 지연**되어 12:00:37에 전환될 수 있습니다. 정상입니다.
- 성공 시 상태 메시지가 갱신되고, 실패 시 실패 사유가 표시됩니다. 창이 숨겨져 있으면 **다음에 창을 열 때** 확인됩니다.

## 5. 데이터 디렉터리와 설정

### 5.1 위치 해석 순서

1. `WALLMAGIC_DATA_DIR` 환경변수 (명시적 오버라이드 — 테스트 격리용)
2. `%LOCALAPPDATA%\WallMagic`
3. `%TEMP%\WallMagic` (폴백)

### 5.2 디렉터리 구조

```
%LOCALAPPDATA%\WallMagic\
├── state.json             # 스냅샷 상태 (previous/current/backend)
├── scenario.json          # 현재 시나리오 설정 (공급자·프롬프트·주기·자격증명)
├── scenario_profiles.json # 자동 전환 프로필 + 규칙 + 전환 이력 (진실의 원천)
├── history.json           # 프롬프트/검색 히스토리
├── library_index.json     # 라이브러리 인덱스 (생성 정보 사이드카 조회용)
├── ui_prefs.json          # UI 환경 설정 (언어 등)
├── active\                # 스테이징 파일 (active_<stem>_<monitor>.bmp)
├── library\               # 생성된 배경 + 검색 기본 루트
└── online_cache\          # 원격 검색으로 내려받은 캐시 이미지
```

### 5.3 `state.json` 스키마

```json
{
  "previous_wallpaper": "C:\\Users\\<user>\\Pictures\\original.jpg",
  "current_wallpaper": "C:\\Users\\<user>\\AppData\\Local\\WallMagic\\active\\active_sunset_primary.bmp",
  "backend_used": "IDesktopWallpaper (COM)"
}
```

| 필드 | 의미 |
|---|---|
| `previous_wallpaper` | 복원용 스냅샷 (원본 사용자 배경) |
| `current_wallpaper` | 마지막으로 적용한 스테이징 경로 |
| `backend_used` | 사용된 API (`IDesktopWallpaper (COM)` / `SystemParametersInfoW (Fallback)` 등) |

### 5.4 `scenario.json` 주요 필드

| 필드 | 의미 |
|---|---|
| `prompt` | 생성 프롬프트 (생성 전용 — 검색어와 무관) |
| `source.search_queries` / `source.next_index` | 순환 검색어 목록 / 커서 |
| `source.urls` / `source.local_dir` | 원격 URL 소스 / 로컬 디렉터리 |
| `provider_order` / `disabled_providers` | 생성 시도 순서 / 공급자 On·Off |
| `seed_mode` / `seed_fixed` / `seed_next` | seed 정책과 값 |
| `interval_secs` | 시나리오 자동 실행 간격 (최소 5분 검증) |
| 모델 선택 | Cloudflare 모델 (flux 여부로 seed 게이팅) |
| `api_token` / `openai_api_key` | 자격증명 — **조회 응답에서는 마스킹**되고, 명시 삭제해야 지워집니다 |

### 5.5 격리 실행 (개발·테스트용)

```powershell
$env:WALLMAGIC_DATA_DIR = "$env:TEMP\wallmagic_sandbox"
cargo run -p wallmagic-app
```
이렇게 하면 상태 파일·프로필·캐시가 샌드박스로 격리되어 실제 사용자 상태를 건드리지 않습니다.

## 6. 문제 해결 (Troubleshooting)

| 증상 | 원인 | 조치 |
|---|---|---|
| 프로그램이 시작되지 않음 | WebView2 미설치 (구형 Win10) | [WebView2 런타임](https://developer.microsoft.com/microsoft-edge/webview2/) 설치 후 재시작 |
| 검색 결과가 비어 있음 | 키워드 불일치 · 폴더에 640×480 이상 이미지 부재 · 확장자 미지원 | 키워드를 비우고 전체 목록 확인, `.jpg/.png/.bmp` 확인 |
| 검색 폴더를 지정해도 결과가 없음 | 경로 오타 · 존재하지 않는 폴더 | 절대 경로 확인 (예: `C:\Users\<user>\Pictures`) |
| 원격 검색 결과가 안 나옴 | 네트워크 차단 · 키워드가 빔(원격 생략) · 원격 응답 실패 | 키워드 입력, 네트워크 확인 — **로컬 결과는 그대로 표시됩니다** |
| 생성이 실패함 | 모든 공급자 실패 (키 미설정·쿼터·네트워크) | 상태 바의 공급자별 실패 사유 확인, `Pollinations`(키 불필요)가 On 인지 확인 |
| "이미지 해상도가 너무 낮습니다" | 640×480 미만 이미지 | 더 큰 이미지 선택 |
| "이미지 디코딩 오류" | 손상된 파일 · 미지원 코덱 | 다른 이미지 사용 |
| 적용이 실패하고 원래대로 돌아감 | COM·SPI 모두 실패 (파일 잠금·권한) | 다른 이미지로 재시도, 네트워크 드라이브면 로컬로 복사 후 시도 |
| 복원이 안 됨 (`스냅샷 없음`) | 한 번도 적용하지 않음 | 정상 동작 — 적용 후 복원 가능 |
| 백엔드 배지가 `Fallback`으로 표시됨 | COM API 실패로 SPI 폴백 사용됨 | 기능은 정상. 문제 지속 시 로그 확인 |
| 창을 닫아도 프로그램이 종료되지 않음 | **트레이 상주 설계** — X는 숨김 처리 | 트레이 아이콘 우클릭 → **종료** (§4.5) |
| 자동 전환이 동작하지 않음 | 규칙 미저장 · 디바운스 미충족 · 쿨다운 중 · 프로필 없음 | **자동 전환 설정 저장** 클릭 → **지금 규칙 평가**로 즉시 확인 (§4.7.2) |
| 시간대 경계에서 늦게 바뀜 | 스케줄러가 **60초 고정 주기** | 정상 동작 — 최대 60초 지연 (§4.7.3) |
| 자동 시작 체크가 저절로 풀려 있음 | OS 시작 프로그램에서 사용자가 직접 해제 | 의도된 동작 — 앱은 OS 실제 상태를 그대로 표시 (§4.6) |

## 8. 알려진 제약 (v1.0.0)

1. **Windows 전용** — macOS/Linux 미지원 (의도된 범위). `targets: "all"` 이지만 서명·공증 설정이 없어 타 플랫폼 산출물은 배포용이 아닙니다.
2. **코드 서명 미적용** — Windows SmartScreen "알 수 없는 게시자" 경고가 표시될 수 있습니다.
3. **자동 업데이트 경로 없음** — 새 버전은 직접 내려받아 재설치해야 합니다.
4. **CSP 미적용** — `tauri.conf.json` 의 `security.csp` 가 `null` 입니다.
5. **API 키 평문 저장** — `scenario.json` 에 평문으로 저장됩니다(암호화 미적용).
6. **`Puter` 공급자는 Rust 백엔드에서 스킵** — 브라우저 SDK 전용이라 UI WebView 경유로만 호출됩니다.
7. **단일 스냅샷** — 복원 대상은 가장 최근 적용 전 상태 1개뿐입니다.
8. **스케줄러 주기 60초 고정** — 사용자가 조정할 수 없습니다. 시간대 경계 전환은 최대 60초 지연됩니다.
9. **히스토리·인덱스는 무제한 증가** — 자동 정리(pruning)가 없습니다.

> 상용 배포 전 남은 항목의 우선순위와 근거는 [`COMMERCIAL_READINESS.md`](./COMMERCIAL_READINESS.md) P0/P1을 참조하세요.

## 9. 부록 — 자주 묻는 질문

**Q. 창을 닫으면 배경이 되돌아가나요?**
A. 아니요. 적용된 배경은 Windows 설정에 영구 저장됩니다. 또한 창을 닫아도 앱은 트레이에 남아 자동 전환을 계속합니다(§4.5).

**Q. 완전히 종료하려면?**
A. 트레이 아이콘 우클릭 → **종료**. 창의 X는 숨김일 뿐입니다.

**Q. 원래 배경으로 되돌리려면?**
A. 프로그램을 실행한 뒤 **이전 배경으로 복원** 버튼을 클릭하세요. 적용 후 PC를 재시작해도 `state.json`에 스냅샷이 남아 있어 복원됩니다.

**Q. 여러 모니터에 각각 다른 배경을 지정할 수 있나요?**
A. 가능합니다. 상단 모니터 드롭다운에서 대상을 지정하고 각각 적용하세요.

**Q. 인터넷 연결이 필요한가요?**
A. **기능에 따라 다릅니다.** 검색(로컬 폴더)·적용·복원·트레이·자동 전환은 **오프라인에서 동작**합니다. 원격 이미지 검색과 AI 생성은 네트워크가 필요하며, 실패해도 로컬 결과·기존 배경은 그대로 유지됩니다.

**Q. 비용이 발생하나요?**
A. **앱 자체에는 결제 기능이 없습니다.** 다만 AI 생성 공급자에 따라 비용이 다릅니다 — `Pollinations` 는 **무료·키 불필요**, `Cloudflare Workers AI`·`OpenAI Images` 는 **사용자가 등록한 키로 각 서비스에 직접 과금**됩니다. 앱은 키를 중계하지 않습니다.

**Q. 생성한 이미지는 어디에 저장되나요?**
A. `%LOCALAPPDATA%\WallMagic\library\` 폴더입니다. 이 폴더는 검색 기본 루트이기도 합니다.

**Q. API 키는 어디에 저장되나요?**
A. `%LOCALAPPDATA%\WallMagic\scenario.json` 에 **평문**으로 저장됩니다. 화면에는 마스킹되어 표시되지만 파일은 암호화되지 않으므로, 공용 PC에서는 사용 후 삭제하세요.
